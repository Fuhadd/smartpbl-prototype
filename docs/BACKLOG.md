# Backlog / Future work

- **TestClient deprecation warning:** Starlette warns that `httpx` with `TestClient` is deprecated and suggests `httpx2`. The swap was not made, because the package needs vetting first (maintainer, provenance). CI (4.4) shows warnings without failing on them; revisit when Starlette removes the httpx path.
- **Readiness endpoint:** `/ready` that checks the DB and Ollama connections (Tier 4).
- **Smaller spaCy model:** `en_core_web_lg` is 425 MB of the 2.3 GB image and of every CI install (uv-cached in 4.4). Try `en_core_web_md` and re-run the redaction tests for recall before switching.
- **Gazetteer integration:** pass client and next-of-kin names from a client registry into `redact(known_names=...)` once persistence exists (Step 1.7+).
- **Consistent pseudonyms within a note** (`<PERSON_1>`, `<PERSON_2>`) if evaluation shows lost relationships hurt safeguarding recall.
- **Project-plan Presidio link** points to `microsoft.github.io/presidio`; the project moved to `presidio.dataprivacystack.org` (verified 2026-11-06).
- **Baseline post-negation** ("Falls: none"): a known gap, left as the 04 exercise.
- **Redaction over-masking in run-on notes:** spaCy tags sentence-initial capitalised words ("Put", "Daughter") as PERSON when notes have no full stops. Consider a minimum PERSON score or a stop-word allowlist.
- **Hybrid extraction:** union the LLM and high-precision rule flags (e.g. the time-comparison late-visit rule) if 1.9 shows they complement each other.
- **Better uncertainty signal:** token log-probs or agreement across samples (n>1 at T>0) instead of self-reported confidence.
- **Missed visit vs safeguarding:** v2 files "no carer attended" under safeguarding. Consider allowing both, or a taxonomy note, after review with PBL.
- **Entailment check** for high-impact categories (safeguarding, falls): does the note support the flag, not just contain the quote? Catches negation errors that grounding misses.
- **Review-vs-escape curve** across routing configurations, for the registered manager to choose an operating point (Step 1.9 / Tier 6).
- **DB roles:** `smartpbl_app` (INSERT/SELECT on audit_events, no ownership/DDL) and a separate migration role (Tier 4).
- **Tamper evidence:** hash-chained audit rows (row_hash = H(prev_hash ‖ row)) plus a verification job, or export to WORM storage.
- **Encryption at rest** for `care_notes.raw_text`, and a **retention job** (delete/anonymise notes after the policy period; audit rows remain).
- **HMAC key management:** move `SMARTPBL_AUDIT_HASH_KEY` to a secrets manager; a key-rotation plan using `hash_alg`/key id.
- **Queue-based processing** with retry/backoff for LLM failures, instead of processing inside the request (Tier 4). `POST /notes` is still synchronous after 1.8; move to 202 + job + polling, with idempotency keys.
- **Note-level sign-off:** a note whose LLM extraction failed and where the baseline found nothing stays in the queue with no flag to act on. Add `POST /review/notes/{id}` (sign off, or re-run extraction).
- **Reviewer-added flags:** let a coordinator add a risk the system missed (the most important label for recall).
- **Correcting a decision:** a manager-only re-open with a reason, audited separately; currently decided flags return 409.
- **Optimistic concurrency (ETag / version column)** for long-lived review screens in the Flutter app (5.2).
- **Queue at scale:** store a priority column, then sort and page in SQL instead of in Python.
- **Raw-text access:** return `raw_text` only to authorised roles, and audit every read (Tier 4.1/4.2).
- **Reviewer analytics:** edit/reject rate per category and per prompt version from `review_decisions`, as a quality and drift signal.
- **Indirect-phrasing failures (from the test evaluation; not tuned on test):** concealed medication ("pills hidden in a tissue"), subtle mood change, shortened visits. Address with new examples drawn from a fresh dev set, then evaluate on a new held-out set. The current test set is spent.
- **qwen2.5:3b:** needs its own prompt tuning and evaluation before it can be a hardware fallback (test recall 0.50 with the llama prompt).
- **Fresh held-out set:** generate a new test split with a different seed and new held-out phrases, for any future prompt or rule iteration.
- **Real-data evaluation plan:** double annotation with kappa, a time-based split, per-category sample-size targets, fairness slices.
- **Scheduling realism:** split shifts with breaks (OR-Tools vehicle breaks), double-up calls (synchronised arrivals), travel mode per carer (walk/bus/drive), paid-travel and working-time rules.
- **Skill-mix-aware generator:** guarantee combination coverage directly, instead of relying on rejection by the validator.
- **Multi-day and multi-seed scenarios** for Tier 2 results that generalise beyond one synthetic day.
- **Time-dependent travel times:** peak-hour factors or historical speed profiles (OSRM `osrm-customize` with traffic CSVs), or a traffic-aware API under a DPA.
- **Door-to-door overhead:** add parking and walking-to-door minutes per visit, calibrated from call-monitoring timestamps.
- **Multimodal travel:** walking and bus carers (Valhalla or OSRM foot profile plus public-transport data).
- **OSRM image tags:** newer OSRM releases (v26.5+) have no published container tags. Re-check before upgrading.
- **Tighter drop bound:** an exact or stronger relaxation that includes travel (CP-SAT circuit on peak windows), to split the 2→11 gap into travel versus heuristic.
- **Costed waiting / span:** `SetSpanCostCoefficientForVehicle` or waiting cost to compress carers' days; measure against travel, drops and continuity.
- **Re-check the metaheuristic choice on other seeds** (tabu vs GLS was one instance).
- **Rolling re-optimisation:** lock assignments and re-plan around short-notice changes.
- **OR-Tools SWIG deprecation warnings** under Python 3.12: track upstream; harmless today.
- **ε-constraint continuity:** minimise travel subject to familiar share ≥ target (CP-SAT, or a counting dimension in routing), to reach non-convex front points and match policy targets.
- **Per-client-group continuity weights:** higher for dementia and end-of-life clients.
- **Week-level continuity:** same carer, same weekday; plan a week rather than a day.
- **Large-w search quality:** more time or a different metaheuristic for w > 30 min, where tabu search degrades.
- **Deterministic solver budget:** time-limited search is not reproducible (3 of 10 sweep points changed on an identical rerun). Use `solution_limit` or fixed-iteration budgets for experiments, or repeat runs and report spread.
- **Same-day re-optimisation:** fast greedy or locked-assignment OR-Tools runs for "who can cover this call now?".
- **Workforce design levers:** split shifts and staggered start times to lift the ~50–55% utilisation that peak demand imposes.
- **Historical-rota evaluation** with real call-monitoring data (KTP proper).
- **Async schedule jobs:** 202 Accepted + status endpoint + worker queue; rate-limit `/schedule/solve` (Tier 4).
