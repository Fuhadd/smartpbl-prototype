# Glossary

- **GGUF**: The file format used by llama.cpp and Ollama for model weights and metadata. It supports quantised tensors.
- **Quantisation**: Storing model weights with fewer bits (e.g. 4-bit instead of 16-bit floats) to cut memory use and speed up inference, at a small cost in accuracy.
- **Q4_K_M**: A llama.cpp "k-quant" scheme: ~4-bit weights in blocks with per-block scales, medium size and quality variant. Typical for Ollama library models.
- **Unified memory**: Apple Silicon design where CPU and GPU share one pool of RAM, so the model's "VRAM" comes out of system memory.
- **Lockfile (`uv.lock`)**: Records the exact versions and hashes of all transitive dependencies for reproducible installs.
- **Dependency group**: A named set of dependencies (e.g. `dev`) in `pyproject.toml` (PEP 735) that is not part of the published package.
- **Liveness vs readiness probe**: Liveness asks "is the process running?" Readiness asks "can it serve traffic?" (e.g. are its dependencies reachable?).
- **12-factor config**: Keeping configuration in environment variables, separate from code, so the same build runs in any environment.
- **Structured output**: LLM output that conforms to a predefined schema (here, JSON matching a Pydantic model).
- **Constrained (grammar-guided) decoding**: Masking, at each generation step, every token that would break a grammar compiled from the schema, so the output is valid by construction.
- **Logits**: The model's raw, unnormalised scores for every vocabulary token at a generation step. Softmax turns them into probabilities.
- **Autoregressive generation**: Producing one token at a time, each conditioned on all the tokens before it. This is why field order in the schema matters.
- **JSON mode**: Constraining output to syntactically valid JSON without enforcing a particular schema.
- **Evidence span**: The verbatim text in the note that supports a flag. It is checked against the source to detect hallucination.
- **Risk taxonomy**: The closed set of risk categories the system may assign.
- **Pseudonymisation**: Replacing direct identifiers with references (e.g. `CL-0001`). Still personal data under UK GDPR, because re-identification is possible with the lookup key.
- **Gold label / ground truth**: The reference answer a prediction is scored against. Here it is correct by construction, from the phrase it came from.
- **Data leakage**: Information from the evaluation set influencing the system being evaluated, which inflates scores. *Phrase leakage* means the same phrase appears in both tuning and test data.
- **Held-out set**: Data kept back from any tuning, used only for final evaluation.
- **Stratification**: Making sure each split has the same proportion of key subgroups (here: risk count and category).
- **Negation detection**: Recognising when a mention is negated ("no signs of falls"). NegEx is a classic rule-based algorithm for it in clinical text.
- **Data card / datasheet**: Structured documentation of a dataset's origin, composition, intended use and limitations.
- **Prevalence**: The proportion of cases that are positive. It strongly affects precision: the same classifier has lower precision when positives are rarer.
- **PII (personally identifiable information)**: Information that identifies a person directly (name, phone, NHS number) or indirectly. UK GDPR uses the broader term "personal data".
- **Special category data**: UK GDPR Art. 9 data needing extra protection, including health data. Care notes are health data.
- **Data minimisation**: UK GDPR Art. 5(1)(c): personal data must be "adequate, relevant and limited to what is necessary" for the purpose.
- **Redaction / de-identification**: Removing or masking identifiers from text. Not the same as anonymisation.
- **Anonymisation vs pseudonymisation**: Anonymous data can't be linked back to a person, so it falls outside GDPR. Pseudonymised data can be re-linked with extra information and is still personal data.
- **NER (named entity recognition)**: Labelling spans of text as entity types (PERSON, LOCATION…), here with a statistical spaCy model.
- **Recogniser (Presidio)**: A component that detects one or more entity types, using regex, deny-lists, checksums or NER, and returns spans with confidence scores.
- **Context enhancement**: Raising a detection's score when supporting words ("nhs", "rang") appear nearby.
- **Deny-list / gazetteer**: An explicit list of strings (e.g. known client and family names) to always detect.
- **Over-redaction**: Masking text that isn't PII, which can destroy clinically relevant meaning.
- **Baseline**: A simple reference method that a more complex one must beat to justify its cost.
- **Lexicon / trigger**: The words or patterns that signal a category (e.g. "fell", "slipped" → falls).
- **NegEx**: A rule-based clinical negation algorithm (Chapman et al., 2001): negation cues within a word window of a finding, with scope terminators and pseudo-negation exceptions.
- **Scope terminator**: A word (e.g. "but") that ends a negation's reach.
- **Pseudo-negation**: A phrase containing a negation word that doesn't negate the finding ("no longer eating" asserts a problem; "NHS no" is a number).
- **Micro vs macro average**: Micro pools counts across classes (frequent classes dominate). Macro averages per-class scores (each class counts equally).
- **Tuning-set optimism**: Performance measured on the data used for design decisions overstates performance on new data.
- **Temperature**: Divides the logits before softmax. T → 0 gives greedy, deterministic decoding; higher T flattens the distribution (more varied output).
- **Greedy decoding**: Always choosing the highest-probability next token.
- **Seed**: Initialises the random number generator used for sampling, so stochastic decoding is repeatable.
- **Prompt versioning**: Treating prompts as versioned artefacts (files, labels, content hashes) recorded with every output.
- **Model digest**: A content hash identifying exact model weights. More reliable than a tag that can be re-pulled.
- **Derived field**: An output field that is a deterministic function of other fields. Computed in code, not generated by the model.
- **Self-consistency (output)**: Whether an output's fields agree with each other (e.g. a high-severity flag implies follow-up).
- **Context window (`num_ctx`)**: The maximum number of tokens (prompt plus output) the model attends to in one request.
- **Grounding (evidence)**: Verifying that the text a model cites actually appears in its source.
- **Hallucination**: Model output that is fluent but not supported by the input or by fact (here: invented evidence or risks).
- **Indel distance**: The minimum number of single-character insertions and deletions to turn one string into another (a substitution costs 2).
- **partial_ratio**: The best similarity between the shorter string and any equal-length window of the longer one.
- **Human-in-the-loop (HITL)**: A design where people review or decide on model outputs before they take effect.
- **Meaningful human involvement**: Under UK GDPR Art. 22A, human input that actually shapes the decision, usually after the automated output, not a rubber stamp.
- **Escape rate**: The share of true risks that are neither correctly auto-accepted nor sent to review, so nobody sees them.
- **Review workload**: The share of notes (or flags) sent to people. It trades off against the escape rate.
- **Data (Use and Access) Act 2025 (DUAA)**: UK law that amended UK GDPR, including replacing Article 22 with Articles 22A–22D on automated decision-making.
- **Append-only log**: A table where rows are only ever inserted, never updated or deleted, so it can serve as evidence.
- **Tamper-resistant vs tamper-evident**: Resistant makes changes hard (triggers, permissions). Evident makes changes detectable afterwards (hash chains, external copies).
- **HMAC**: Keyed hash (`H((K⊕opad)‖H((K⊕ipad)‖m))`). Without the key you can't compute or check a tag.
- **Dictionary attack (on hashes)**: Hashing likely inputs and comparing them with stored hashes to recover low-entropy originals.
- **Migration (Alembic)**: A versioned, reversible script that changes the database schema.
- **Autogenerate**: Alembic comparing models with the database to draft a migration. It misses triggers and some constraints, so review it.
- **CHECK constraint**: A database rule that rejects rows violating a condition (e.g. severity ∈ {low, medium, high}).
- **Savepoint**: A nested transaction marker that can be rolled back without ending the outer transaction.
- **Storage limitation**: UK GDPR Art. 5(1)(e): keep identifiable data no longer than necessary.
- **Event sourcing**: An architecture where state is derived by replaying an event log, rather than stored directly.
- **Lost update**: Two transactions read the same row and both write; the later write silently overwrites the earlier one.
- **Pessimistic locking (`SELECT … FOR UPDATE`)**: Lock the row when reading it, so other writers wait until the transaction ends.
- **Optimistic concurrency**: No lock; each write checks that a version number (or ETag) is unchanged since the read, and fails if it isn't.
- **Dependency override (FastAPI)**: Replacing a dependency function with another one, e.g. in tests (`app.dependency_overrides`).
- **Excessive data exposure (OWASP API3:2023)**: An API returning object properties the caller doesn't need or shouldn't see.
- **HTTP 409 Conflict**: The request conflicts with the resource's current state (e.g. the flag was already reviewed, or the note ID already exists).
- **HTTP 422 Unprocessable Content**: The request is well-formed but its content fails validation.
- **Idempotency key**: A client-supplied ID that lets a server recognise retries of the same request and apply it only once.
- **Micro average**: Pool TP/FP/FN across categories, then compute the metric; frequent categories dominate.
- **Macro average**: Compute the metric per category, then take the unweighted mean; every category counts equally.
- **F-beta (F2)**: A weighted harmonic mean of precision and recall; β = 2 weights recall four times as heavily as precision.
- **Bootstrap confidence interval**: An interval from recomputing a metric on many resamples (with replacement) of the test set.
- **Paired bootstrap**: Resampling the same items for two systems and recording the difference, so per-item difficulty cancels out.
- **Escape rate**: Share of true risks that no part of the pipeline flags, so no human will be prompted to see them.
- **Alert fatigue**: Reviewers ignoring or rubber-stamping alerts because too many are false.
- **Union recall**: Recall when the flags of two systems are combined.
- **Inter-annotator agreement (Cohen's kappa)**: Agreement between two labellers corrected for chance; caps how well any model can be judged.
- **Domiciliary care (homecare)**: Care delivered in a person's own home through scheduled visits ("calls").
- **Arrival (time) window**: The interval in which a carer must arrive for a visit.
- **Time-critical medication**: Medication whose timing matters clinically (e.g. Parkinson's); modelled as a narrow window.
- **Double-up call**: A visit needing two carers at once (e.g. hoist transfers); requires synchronised arrivals.
- **Split shift**: A working day in two parts with an unpaid gap (e.g. morning and evening).
- **Hard / soft constraint**: A rule that must hold, versus a preference that is traded off through a cost.
- **Skill-mix coverage**: Whether some single carer has every skill a visit needs, not just whether each skill exists somewhere on shift.
- **Continuity of care**: Being supported by the same small group of familiar carers.
- **OSRM**: Open Source Routing Machine, a fast routing engine over OpenStreetMap data, with route, table, match and trip services.
- **Table (matrix) service**: One request returning travel durations and distances for all source–destination pairs.
- **Haversine distance**: Great-circle (straight-line over the Earth's surface) distance between two coordinates.
- **Circuity / detour factor**: Road distance divided by straight-line distance (median 1.34 here).
- **Free-flow speed**: Travel speed with no traffic; what OSRM's car profile models.
- **Contraction hierarchies (CH)**: Routing preprocessing that adds shortcut edges by node importance; very fast queries, slow reweighting.
- **Multi-level Dijkstra (MLD)**: Routing preprocessing using nested graph partitions; fast reweighting (customisation) and good query speed.
- **Asymmetric matrix**: Travel times where A→B ≠ B→A (one-way streets, turn restrictions).
