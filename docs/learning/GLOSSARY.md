# Glossary

- **GGUF**: The file format used by llama.cpp and Ollama for model weights and metadata. It supports quantised tensors.
- **Quantisation**: Storing model weights with fewer bits (e.g. 4-bit instead of 16-bit floats) to cut memory use and speed up inference, at a small cost in accuracy.
- **Q4_K_M**: A llama.cpp "k-quant" scheme: ~4-bit weights in blocks with per-block scales, medium size and quality variant. Typical for Ollama library models.
- **Unified memory**: Apple Silicon design where CPU and GPU share one pool of RAM, so the model's "VRAM" comes out of system memory.
- **Lockfile (`uv.lock`)**: Records the exact versions and hashes of all transitive dependencies for reproducible installs.
- **Dependency group**: A named set of dependencies (e.g. `dev`) in `pyproject.toml` (PEP 735) that is not part of the published package.
- **Liveness vs readiness probe**: Liveness asks "is the process running?" Readiness asks "can it serve traffic?" (e.g. are its dependencies reachable?).
- **12-factor config**: Keeping configuration in environment variables, separate from code, so the same build runs in any environment.
- **Structured output**: LLM output that conforms to a predefined schema (here, JSON matching a Pydantic model).
- **Constrained (grammar-guided) decoding**: Masking, at each generation step, every token that would break a grammar compiled from the schema, so the output is valid by construction.
- **Logits**: The model's raw, unnormalised scores for every vocabulary token at a generation step. Softmax turns them into probabilities.
- **Autoregressive generation**: Producing one token at a time, each conditioned on all the tokens before it. This is why field order in the schema matters.
- **JSON mode**: Constraining output to syntactically valid JSON without enforcing a particular schema.
- **Evidence span**: The verbatim text in the note that supports a flag. It is checked against the source to detect hallucination.
- **Risk taxonomy**: The closed set of risk categories the system may assign.
- **Pseudonymisation**: Replacing direct identifiers with references (e.g. `CL-0001`). Still personal data under UK GDPR, because re-identification is possible with the lookup key.
- **Gold label / ground truth**: The reference answer a prediction is scored against. Here it is correct by construction, from the phrase it came from.
- **Data leakage**: Information from the evaluation set influencing the system being evaluated, which inflates scores. *Phrase leakage* means the same phrase appears in both tuning and test data.
- **Held-out set**: Data kept back from any tuning, used only for final evaluation.
- **Stratification**: Making sure each split has the same proportion of key subgroups (here: risk count and category).
- **Negation detection**: Recognising when a mention is negated ("no signs of falls"). NegEx is a classic rule-based algorithm for it in clinical text.
- **Data card / datasheet**: Structured documentation of a dataset's origin, composition, intended use and limitations.
- **Prevalence**: The proportion of cases that are positive. It strongly affects precision: the same classifier has lower precision when positives are rarer.
- **PII (personally identifiable information)**: Information that identifies a person directly (name, phone, NHS number) or indirectly. UK GDPR uses the broader term "personal data".
- **Special category data**: UK GDPR Art. 9 data needing extra protection, including health data. Care notes are health data.
- **Data minimisation**: UK GDPR Art. 5(1)(c): personal data must be "adequate, relevant and limited to what is necessary" for the purpose.
- **Redaction / de-identification**: Removing or masking identifiers from text. Not the same as anonymisation.
- **Anonymisation vs pseudonymisation**: Anonymous data can't be linked back to a person, so it falls outside GDPR. Pseudonymised data can be re-linked with extra information and is still personal data.
- **NER (named entity recognition)**: Labelling spans of text as entity types (PERSON, LOCATION…), here with a statistical spaCy model.
- **Recogniser (Presidio)**: A component that detects one or more entity types, using regex, deny-lists, checksums or NER, and returns spans with confidence scores.
- **Context enhancement**: Raising a detection's score when supporting words ("nhs", "rang") appear nearby.
- **Deny-list / gazetteer**: An explicit list of strings (e.g. known client and family names) to always detect.
- **Over-redaction**: Masking text that isn't PII, which can destroy clinically relevant meaning.
- **Baseline**: A simple reference method that a more complex one must beat to justify its cost.
- **Lexicon / trigger**: The words or patterns that signal a category (e.g. "fell", "slipped" → falls).
- **NegEx**: A rule-based clinical negation algorithm (Chapman et al., 2001): negation cues within a word window of a finding, with scope terminators and pseudo-negation exceptions.
- **Scope terminator**: A word (e.g. "but") that ends a negation's reach.
- **Pseudo-negation**: A phrase containing a negation word that doesn't negate the finding ("no longer eating" asserts a problem; "NHS no" is a number).
- **Micro vs macro average**: Micro pools counts across classes (frequent classes dominate). Macro averages per-class scores (each class counts equally).
- **Tuning-set optimism**: Performance measured on the data used for design decisions overstates performance on new data.
- **Temperature**: Divides the logits before softmax. T → 0 gives greedy, deterministic decoding; higher T flattens the distribution (more varied output).
- **Greedy decoding**: Always choosing the highest-probability next token.
- **Seed**: Initialises the random number generator used for sampling, so stochastic decoding is repeatable.
- **Prompt versioning**: Treating prompts as versioned artefacts (files, labels, content hashes) recorded with every output.
- **Model digest**: A content hash identifying exact model weights. More reliable than a tag that can be re-pulled.
- **Derived field**: An output field that is a deterministic function of other fields. Computed in code, not generated by the model.
- **Self-consistency (output)**: Whether an output's fields agree with each other (e.g. a high-severity flag implies follow-up).
- **Context window (`num_ctx`)**: The maximum number of tokens (prompt plus output) the model attends to in one request.
- **Grounding (evidence)**: Verifying that the text a model cites actually appears in its source.
- **Hallucination**: Model output that is fluent but not supported by the input or by fact (here: invented evidence or risks).
- **Indel distance**: The minimum number of single-character insertions and deletions to turn one string into another (a substitution costs 2).
- **partial_ratio**: The best similarity between the shorter string and any equal-length window of the longer one.
- **Human-in-the-loop (HITL)**: A design where people review or decide on model outputs before they take effect.
- **Meaningful human involvement**: Under UK GDPR Art. 22A, human input that actually shapes the decision, usually after the automated output, not a rubber stamp.
- **Escape rate**: The share of true risks that are neither correctly auto-accepted nor sent to review, so nobody sees them.
- **Review workload**: The share of notes (or flags) sent to people. It trades off against the escape rate.
- **Data (Use and Access) Act 2025 (DUAA)**: UK law that amended UK GDPR, including replacing Article 22 with Articles 22A–22D on automated decision-making.
- **Append-only log**: A table where rows are only ever inserted, never updated or deleted, so it can serve as evidence.
- **Tamper-resistant vs tamper-evident**: Resistant makes changes hard (triggers, permissions). Evident makes changes detectable afterwards (hash chains, external copies).
- **HMAC**: Keyed hash (`H((K⊕opad)‖H((K⊕ipad)‖m))`). Without the key you can't compute or check a tag.
- **Dictionary attack (on hashes)**: Hashing likely inputs and comparing them with stored hashes to recover low-entropy originals.
- **Migration (Alembic)**: A versioned, reversible script that changes the database schema.
- **Autogenerate**: Alembic comparing models with the database to draft a migration. It misses triggers and some constraints, so review it.
- **CHECK constraint**: A database rule that rejects rows violating a condition (e.g. severity ∈ {low, medium, high}).
- **Savepoint**: A nested transaction marker that can be rolled back without ending the outer transaction.
- **Storage limitation**: UK GDPR Art. 5(1)(e): keep identifiable data no longer than necessary.
- **Event sourcing**: An architecture where state is derived by replaying an event log, rather than stored directly.
- **Lost update**: Two transactions read the same row and both write; the later write silently overwrites the earlier one.
- **Pessimistic locking (`SELECT … FOR UPDATE`)**: Lock the row when reading it, so other writers wait until the transaction ends.
- **Optimistic concurrency**: No lock; each write checks that a version number (or ETag) is unchanged since the read, and fails if it isn't.
- **Dependency override (FastAPI)**: Replacing a dependency function with another one, e.g. in tests (`app.dependency_overrides`).
- **Excessive data exposure (OWASP API3:2023)**: An API returning object properties the caller doesn't need or shouldn't see.
- **HTTP 409 Conflict**: The request conflicts with the resource's current state (e.g. the flag was already reviewed, or the note ID already exists).
- **HTTP 422 Unprocessable Content**: The request is well-formed but its content fails validation.
- **Idempotency key**: A client-supplied ID that lets a server recognise retries of the same request and apply it only once.
- **Micro average**: Pool TP/FP/FN across categories, then compute the metric; frequent categories dominate.
- **Macro average**: Compute the metric per category, then take the unweighted mean; every category counts equally.
- **F-beta (F2)**: A weighted harmonic mean of precision and recall; β = 2 weights recall four times as heavily as precision.
- **Bootstrap confidence interval**: An interval from recomputing a metric on many resamples (with replacement) of the test set.
- **Paired bootstrap**: Resampling the same items for two systems and recording the difference, so per-item difficulty cancels out.
- **Escape rate**: Share of true risks that no part of the pipeline flags, so no human will be prompted to see them.
- **Alert fatigue**: Reviewers ignoring or rubber-stamping alerts because too many are false.
- **Union recall**: Recall when the flags of two systems are combined.
- **Inter-annotator agreement (Cohen's kappa)**: Agreement between two labellers corrected for chance; caps how well any model can be judged.
- **Domiciliary care (homecare)**: Care delivered in a person's own home through scheduled visits ("calls").
- **Arrival (time) window**: The interval in which a carer must arrive for a visit.
- **Time-critical medication**: Medication whose timing matters clinically (e.g. Parkinson's); modelled as a narrow window.
- **Double-up call**: A visit needing two carers at once (e.g. hoist transfers); requires synchronised arrivals.
- **Split shift**: A working day in two parts with an unpaid gap (e.g. morning and evening).
- **Hard / soft constraint**: A rule that must hold, versus a preference that is traded off through a cost.
- **Skill-mix coverage**: Whether some single carer has every skill a visit needs, not just whether each skill exists somewhere on shift.
- **Continuity of care**: Being supported by the same small group of familiar carers.
- **OSRM**: Open Source Routing Machine, a fast routing engine over OpenStreetMap data, with route, table, match and trip services.
- **Table (matrix) service**: One request returning travel durations and distances for all source–destination pairs.
- **Haversine distance**: Great-circle (straight-line over the Earth's surface) distance between two coordinates.
- **Circuity / detour factor**: Road distance divided by straight-line distance (median 1.34 here).
- **Free-flow speed**: Travel speed with no traffic; what OSRM's car profile models.
- **Contraction hierarchies (CH)**: Routing preprocessing that adds shortcut edges by node importance; very fast queries, slow reweighting.
- **Multi-level Dijkstra (MLD)**: Routing preprocessing using nested graph partitions; fast reweighting (customisation) and good query speed.
- **Asymmetric matrix**: Travel times where A→B ≠ B→A (one-way streets, turn restrictions).
- **VRPTW**: Vehicle routing problem with time windows; NP-hard generalisation of the travelling salesman problem.
- **Dimension (OR-Tools)**: A quantity accumulated along routes (here time); `cumul(j) ≥ cumul(i) + transit(i,j)` with optional slack.
- **Disjunction / drop penalty**: Makes a node optional; leaving it out adds a penalty to the objective.
- **First-solution strategy**: Construction heuristic producing the initial complete solution (e.g. parallel cheapest insertion, savings).
- **Local search**: Repeatedly applying small moves (relocate, exchange, 2-opt) while they improve the cost.
- **Metaheuristic**: A strategy to escape local minima: guided local search, tabu search, simulated annealing.
- **Open route**: A route that ends at its last stop (no return to depot or home).
- **Relaxation / lower bound**: An easier version of a problem (e.g. zero travel) whose optimum bounds what the real problem can achieve.
- **CP-SAT**: OR-Tools' constraint-programming solver over integer variables; exact, with proofs of optimality.
- **Multi-objective optimisation**: Optimising several conflicting goals at once; the answer is a set of trade-offs, not one optimum.
- **Pareto-optimal / non-dominated**: A solution no other solution beats on one objective without being worse on another.
- **Pareto front**: The set of Pareto-optimal solutions; choosing among them is a value judgement.
- **Weighted-sum method**: Combine objectives as cost₁ + w × cost₂ and sweep w; finds only points on the convex hull of the front.
- **ε-constraint method**: Optimise one objective subject to the others meeting thresholds; can reach non-convex front regions.
- **Lexicographic optimisation**: Optimise objectives in priority order, fixing each before the next (here: coverage, then the travel/continuity trade-off).
- **Warm start**: Starting a solver from an existing solution; with an improving search the result is never worse than the start.
- **Knee point**: Where the marginal cost of improving one objective rises sharply.
- **Greedy heuristic**: Builds a solution by making the locally best choice at each step, never revisiting it.
- **Myopia (heuristics)**: Failing to account for how a choice now constrains later choices.
- **Regret insertion**: Insert first the visit whose best and second-best options differ most (the one you'd regret postponing).
- **Utilisation**: Share of paid shift time spent on visits and driving.
- **Shadow mode**: Running a new system alongside the current process, without acting on its outputs, to compare decisions.
- **Explainability (operational)**: Giving checkable reasons for each automated decision, in terms users understand.
- **Counterfactual explanation**: What would change if a different choice were made ("CR-0007 would add 14 minutes").
- **Canonical serialisation**: A single, deterministic encoding of equal data (e.g. sorted sets), so hashes are stable.
- **Finaliser (OR-Tools)**: A secondary preference applied after the search, used to pick exact values (such as times) within a fixed solution.
- **Attrition (turnover)**: Staff leaving an employer; here, a carer leaving within 12 months of a snapshot date.
- **Snapshot date / label window**: Features use data from before the snapshot only; the label covers a fixed period after it.
- **Known-mechanism (ground-truth) generator**: Synthetic data whose label is produced by a documented rule, so you can check what a model recovers.
- **Circularity (synthetic evaluation)**: A model trained and tested on generated data learns the generator; good scores show the pipeline works, not that the world works that way.
- **Oracle (Bayes-optimal) probability**: The best possible prediction from the observed features, P(y | x), averaging over unobserved factors; it sets the ceiling for AUC and the target for calibration.
- **Latent (unobserved) factor**: A cause of the outcome that no feature records; it lowers the achievable accuracy.
- **Irreducible (aleatoric) noise**: Randomness in the outcome itself; a 40%-risk carer may or may not leave, whatever the model.
- **Gauss–Hermite quadrature**: Computing an average over a normal distribution exactly enough with a weighted sum at a few fixed points.
- **Null feature**: A feature with no true effect, included to test whether models and explanations wrongly assign it importance.
- **Interaction effect**: One feature's effect depends on another's value (short-notice changes hurt more on zero-hours contracts).
- **Hinge (piecewise-linear) effect**: Zero below a threshold, linear above it, e.g. max(0, changes − 2).
- **Stratified split**: A train/test split that keeps the class proportions the same in both parts.
- **Protected characteristic**: An attribute protected by the Equality Act 2010 (e.g. age, sex, race); kept here for auditing only.
- **Proxy discrimination (indirect discrimination)**: Disadvantaging a protected group through features correlated with membership, even when the attribute itself is excluded.
- **Censoring**: Not seeing the outcome for some people because the observation period ended (e.g. recent hires); survival analysis handles it.
- **Data card / datasheet**: Documentation of how a dataset was made, what it contains, and its known biases and intended uses.
- **Nested cross-validation**: An outer CV loop for evaluation with hyperparameter search run inside each outer training fold, so the estimate covers the tuning procedure without optimism.
- **Repeated stratified k-fold**: k-fold CV repeated with different shuffles, each fold keeping the class proportions; it reduces the variance of the estimate.
- **Paired comparison (CV)**: Comparing two models fold by fold on identical splits, so fold difficulty cancels out.
- **Logistic regression**: A linear model of the log-odds; transparent coefficients, but it can't represent steps or interactions unless they are engineered as features.
- **Histogram gradient boosting (HGB)**: An ensemble of small trees, each fitted to the gradient of the loss of the ensemble so far, with features binned into histograms for speed.
- **Log loss (cross-entropy)**: −mean[y·log p + (1−y)·log(1−p)]; a proper scoring rule that heavily penalises confident wrong probabilities.
- **Class imbalance**: One class is much rarer than the other; it affects which metrics are informative more than which model to use.
- **Class weighting**: Scaling each class's loss (e.g. to 50:50); it shifts probabilities and the threshold, rarely the ranking.
- **SMOTE**: Synthetic Minority Over-sampling Technique; creates artificial minority rows by interpolation. It distorts probabilities in a similar way to class weighting.
- **ROC-AUC**: The probability that a random positive is ranked above a random negative; insensitive to the base rate.
- **Precision–recall curve / average precision (AP)**: Precision against recall across thresholds; AP = Σ(Rₙ−Rₙ₋₁)·Pₙ. Chance level is the base rate.
- **Precision at top-k**: The positive rate among the k highest-scored cases; what a fixed intervention budget buys.
- **Calibration**: Predicted probabilities match observed frequencies (of those given 30%, about 30% leave).
- **Reliability diagram (calibration curve)**: Mean predicted probability against observed rate, per bin.
- **Brier score**: Mean squared error of probabilities, (p−y)²; mixes calibration and discrimination. The base-rate predictor scores p(1−p).
- **Post-hoc calibration**: Re-mapping a model's scores to probabilities (Platt/sigmoid or isotonic) on held-out data.
- **Bootstrap confidence interval**: Resampling rows with replacement to estimate the sampling spread of a metric.
- **Shapley value**: A feature's marginal contribution to a prediction, averaged over all orders of adding features; the unique attribution with efficiency, symmetry, dummy and additivity properties.
- **SHAP**: SHapley Additive exPlanations; Shapley values for model predictions, with fast exact algorithms for trees (TreeSHAP).
- **Additivity / efficiency (SHAP)**: Base value + sum of a row's SHAP values = the model's output for that row.
- **Base value (SHAP)**: The model's average output over the background distribution; where every explanation starts.
- **Interventional vs path-dependent SHAP**: Interventional replaces "unknown" features with values from a background sample, independently of the known ones; path-dependent uses the trees' training-leaf counts, so it follows the data's correlations.
- **Local vs global explanation**: Why this one prediction (waterfall) vs how the model behaves overall (beeswarm, mean |SHAP|).
- **Beeswarm plot**: One dot per row per feature, at its SHAP value, coloured by the feature value.
- **Waterfall plot**: One row's explanation as steps from the base value to the model output.
- **Attribution swapping (correlated features)**: When two features carry the same signal, the model and its explanations may credit either, so importance moves between them.
- **Model card**: A short document of a model's intended use, out-of-scope uses, evaluation, factors, ethical considerations and caveats.
- **Selection rate / four-fifths heuristic**: The share of a group flagged; a group selected at under 80% of the most-selected group's rate suggests adverse impact (a screening rule, not a legal test).
- **Accurate and disparate**: A model can be calibrated within every group and still select groups at very different rates, because base rates differ.
- **Self-fulfilling prediction (feedback loop)**: Acting on a prediction changes the outcome it predicted, e.g. cutting shifts for "likely leavers" makes them leave.
- **Out-of-sample scoring**: Serving predictions only for people the model wasn't trained on, so scores reflect real generalisation.
- **Model version digest**: A hash of everything that determines a fitted model (data, code settings, library versions), recorded with every prediction or view.
- **Pickle deserialisation risk**: Loading a pickle can execute arbitrary code, so pickled models must only come from trusted, verified sources.
- **skops**: A scikit-learn persistence format that loads only explicitly trusted types, avoiding pickle's arbitrary-code risk.
- **Model registry**: A store of versioned model artefacts with lineage and stage (staging, production), e.g. MLflow.
- **Audit on read**: Logging who accessed sensitive data, not only who changed it.
- **Broken Object Property Level Authorization (OWASP API3:2023)**: Exposing (or allowing writes to) object fields a client shouldn't see; prevented by explicit response schemas.
- **Jensen's inequality (here)**: For a convex function f, mean(f(x)) ≥ f(mean(x)); so the mean of probabilities differs from the probability of the mean log-odds.
- **Cold start**: The extra latency of the first request while a process initialises (here, training the model).
- **Authentication vs authorisation**: Authentication proves who a caller is (a valid token); authorisation decides what they may do (role → permission). They map to HTTP 401 and 403.
- **JWT (JSON Web Token)**: `header.payload.signature`, base64url-encoded. The payload is readable by anyone; the signature (here HMAC-SHA256) proves it wasn't changed.
- **Claims (`sub`, `exp`, `iat`, `iss`, `aud`, `jti`)**: Subject (user id), expiry, issued-at, issuer, intended audience and a unique token id.
- **`alg: none` / algorithm confusion**: Attacks where the token header chooses a weak or no algorithm. Prevented by the server pinning the allowed algorithms.
- **Cross-JWT confusion**: Using a token issued for one purpose (refresh) as another (access). Prevented by a type claim and mutually exclusive validation rules.
- **Access vs refresh token**: A short-lived token sent with every request, and a longer-lived one used only to get new access tokens.
- **Refresh token rotation**: Each refresh token is single use; exchanging it issues a new one and invalidates the old.
- **Token family / reuse detection**: All refresh tokens from one login. Presenting an already-rotated token signals theft, so the whole family is revoked.
- **RBAC (role-based access control)**: Permissions are granted to roles, and users get roles, so the policy is a small table rather than per-user rules.
- **Least privilege**: Each role gets only the permissions its job needs.
- **Separation of duties**: Splitting acting (deciding flags, running the solver) from overseeing (audit, risk review) between roles.
- **Deny by default**: Every endpoint is closed unless a permission explicitly opens it; enforced here by a guard test.
- **Argon2id**: A memory-hard password hashing function (winner of the Password Hashing Competition). Each guess costs memory as well as CPU, which slows GPU cracking.
- **Salt**: Random data stored with each password hash, so equal passwords give different hashes and precomputed (rainbow) tables don't work.
- **Username enumeration**: Learning which accounts exist from differences in error messages or response times.
- **BOLA / BFLA (OWASP API1 / API5)**: Broken Object-Level Authorization (accessing someone else's record) vs Broken Function-Level Authorization (calling an endpoint your role shouldn't reach).
- **OIDC (OpenID Connect)**: An identity layer on OAuth 2.0, used for single sign-on with an external identity provider such as Microsoft Entra ID.
- **ASGI**: Python's async server interface: an app is `async (scope, receive, send)`, and the response is a sequence of messages (`http.response.start`, `http.response.body`).
- **Pure ASGI middleware**: A wrapper app that intercepts `receive`/`send` directly; full control over the response, and context variables propagate correctly (unlike `BaseHTTPMiddleware`).
- **Request (correlation) id**: A unique id per request, attached to every log or audit record it causes and returned to the client, so related events can be joined.
- **Context variable (`contextvars`)**: Per-task "global" state that async tasks and worker threads inherit as a copy; downstream `set()` doesn't reach the caller, but mutating a shared object does.
- **Fail closed / fail open**: On a failure of a safety mechanism, refuse the operation (closed) or let it proceed (open).
- **Access log vs decision log**: Who requested what, and with what outcome, vs what a model or person decided and on what basis; joined here by request id.
- **Subject (audit)**: The record an event is about, as a typed id (`care_note`, `carer`, …), so "who touched X?" is one indexed query.
- **Route template**: The declared path (`/notes/{note_id}`) rather than the concrete URL; stable for grouping and free of ids or query text.
- **SIEM**: Security Information and Event Management: central collection, search and alerting over security logs.
- **pgaudit**: A PostgreSQL extension that logs SQL statements by database role; sees DBA activity the application can't.
